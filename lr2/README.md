## Инструкции по запуску

Для запуска данного сервиса надо находиться в этой директории (lr2)

**Первый запуск**

1) создать .env файл, скопировав .env.example
2) запустить все сервисы через docker
    ```shell
    docker compose up --build -d
    ```
3) создать базы данных внутри postgres
    ```sql
    create database orders_db;
    create database users_db;
    create database products_db;
    ```
4) поменять в .env файле значение POSTGRES_HOST на `localhost` (особенности работы с
   сетями внутри docker stack'a)
5) Зайти в каждый сервис и произвести этот скрипт, если установлен uv

```shell
uv run --with alembic --with dotenv --with sqlmodel --with psycopg2-binary alembic upgrade head
```

Или любым другим способом применить миграции на бд.

Эти процедуры создадут новый docker volume `pgdata` на вашем устройстве. Это позволит
сохранять содержание базы данных между запусками

**Повторные запуски**

Для повторного запуска требуется только лишь пересобрать docker stack:

```shell
docker compose down && docker compose up --build -d
```

## Стандартная конфигурация

Для разработки я оставил возможность индивидуально обращаться к каждому микросервису.
Для теоретического `prod` деплоя можно удалить прокидывание портов для сервисов и базы
данных, так как они не должны общаться с внешним миром (за пределом docker stack'a)

В текущей конфигурации, доступ к каждому сервису можно получить следующим образом:

**Пользователи**

base url: `http://0.0.0.0:8001/`

Пути:

``` 
/users/
   [GET] - список всех пользователей
   [POST] - создать нового пользователя
   /<id>/
      [GET] - информация о пользователе
      [PATCH] - обновить информацию о пользователе
      [DELETE] - удалить пользователя
```

**Продукты**

base url: `http://0.0.0.0:8002/`

Пути:

``` 
/products/
   [GET] - список всех продуктов
   [POST] - создать новый продукт
   /<id>/
      [GET] - информация о продукте
      [PATCH] - обновить информацию о продукте
      [DELETE] - удалить продукт
```

**Заказы**

base url: `http://0.0.0.0:8003/`

Пути:

``` 
/orders/
   [GET] - список всех заказов
   [POST] - создать новый заказ
   /<id>/
      [GET] - информация о заказе
      [PATCH] - обновить информацию о заказе
      [DELETE] - удалить заказ
```

**Gateway**

base url: `http://0.0.0.0:4000/graphql/`

**Frontend**

base url: `http://0.0.0.0:3000/`

## Векторы развития

Как я и упоминал, для полноценного деплоя стоит убрать прокидывание портов из докера
для сервисов, так как они не должны общаться с внешним миром. Также можно добавить
автоматическое создание и применение миграций при сборке контейнеров. У каждого
микросервиса должна быть своя база данных, чего я не сделал (все на одном узле,
хотя все данные вынесены в отдельные схемы).

Frontend стоит вынести в отдельный сервис, а также стоит зафиксировать адрес gateway в
переменных окружения. Также стоит обновить интерфейс.
